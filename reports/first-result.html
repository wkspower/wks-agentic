Pet shop features and capabilities

Scope decided in round 1 (Q9): sell animals and products to registered customers and keep the stock right. Python 3 standard library, command line, state in a local file; no network, no real money, no real personal data.

For the product owner: what works today

CapabilityStatusWhat that means
Keep a catalog of what the shop sells✓ builtAdd an animal or a product with an id, a name and a price in cents. Look one up. Change a price. List everything in id order. Duplicate ids, empty names, unknown kinds and invalid prices are refused, and a refusal changes nothing.
Track stock○ specified, not builtReceive and remove quantities per item; never below zero.
Register customers○ specified, not builtName only; ids C1, C2… never reused; search by part of a name.
Sell○ specified, not builtA sale of several lines to one customer, with the right total, taken from stock wholly or not at all.
Run the shop from the command line○ specified, not builtadd-item, receive, register, sell, stock, takings, with the state saved to a file.

Nothing can be used by a shopkeeper yet. The catalog is a library module with no command line of its own; the usable product appears only when the shop unit is built on top of the four modules.

"×2" means every case runs twice: once plainly and once with the state passed through JSON at each step.

Design decisions that hold for all five units

DecisionConsequence
Modules hold no stateEvery function takes the state as its first argument. The state is created only by new(), is opaque to callers, and survives a JSON round trip, so the shop can persist it without knowing its shape.
No unit imports anotherSales gets prices and stock through three callables supplied by the shop. Each module can be built, tested and replaced alone; the measures check imports with ast.
Refusals are atomicA refused call changes nothing, at module level and at the command line (state file byte-identical).
Returned data are copiesCallers cannot corrupt the state by editing what they were given.
Money is integer centsNo floats anywhere in prices or totals.
The shop is tested as a black boxIts measure runs python3 shop.py --state FILE … from outside, so internal structure is free to change.

What the machinery caught, and what it does not cover

CaughtThe enforcer's own undo was broken while its verdict passed. The measure gained 20 cases and 8 planted wrong undos before the fix was allowed to stand.
CaughtThe repaired undo showed that an earlier installation cannot be reverted once the judge has logged a later one, because all decisions share one file. Recorded as a limit; not fixed.
CaughtMeasure writers reported gaps in the documents; five became rules before any build.
Not coveredOne session gave every unit its declarations and built the judge and the enforcer. The other agents were separate runs of the same model.
Not coveredNothing forces a call to the enforcer, and nothing verifies who made a change.
Not coveredError numbers are unknown for the enforcer and for every measure except catalog's.
