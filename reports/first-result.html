Pet shop features and capabilities

Scope decided in round 1 (Q9): sell animals and products to registered customers and keep the stock right. Python 3 standard library, command line, state in a local file; no network, no real money, no real personal data.

For the product owner: what works today

CapabilityCommandBehaviour
Add something to selladd-item ID NAME KIND PRICE_CENTSKind is animal or product. Duplicate ids, other kinds, negative or non-integer prices are refused.
Receive stockreceive ID QUANTITYPrints the quantity now on hand. Refused for an item not in the catalog or a quantity below 1.
Register a customerregister NAMEPrints the new id: C1, C2, … Blank names refused. Two customers may share a name.
Sellsell CUSTOMER_ID ID=QTY [ID=QTY …]Prints the sale id and the total in cents. Refused wholly if the customer or an item is unknown, or if the quantities asked of one item, summed over the lines, exceed the stock. A refused sale uses no sale id.
Check stockstock IDPrints the quantity on hand.
See the takingstakingsPrints the sum of all sales in cents.

Every command is run as python3 shop.py --state FILE COMMAND …. Success prints one line and exits 0. Any refusal exits 1 with a message on stderr and leaves the state file exactly as it was.

What the shop does not do

Not reachable from the command lineListing the catalog, changing a price, searching customers and looking up a past sale exist in the modules but have no command.
Not in scopeReturns, refunds, removing items or customers, discounts, services by appointment, payments.
Operational limitsOne user at a time. The state file is written directly, not atomically, so a crash mid-write can corrupt it. A corrupt state file is refused, not repaired.

Design decisions that hold for all five units

DecisionConsequence
Modules hold no stateEvery function takes the state first. The state is made only by new(), is opaque to callers and survives a JSON round trip. The shop stores the four states in one JSON object and never looks inside them.
No unit imports anotherSales gets prices and stock through three callables the shop supplies. Each module was built, tested and selected alone; the measures check imports with ast.
Refusals are atomicA refused call changes nothing in a module; a refused command leaves the state file byte-identical. The shop writes the file only after a command fully succeeds.
Returned data are copiesCallers cannot corrupt the state by editing what they were given.
Money is integer centsNo floats in prices or totals.
The shop is tested as a black boxIts measure and its audit run the program from outside, so its internals are free to change.

Decisions the builders made that are not yet rules

The documents were silent on these. Both builders of each unit decided alike, but nothing yet stops a later builder deciding differently.

ShopNumbers are ASCII digits only (+5, 1_000 refused). --state FILE must come first. A sell line is split at its last =. register takes the name as one argument. The state file is rewritten after every successful command, read-only ones included.
Stockon_hand returns 0 for any id that is not a non-empty string.
Customersget with a non-string id is KeyError; find with a non-string text returns nothing; case is ignored with casefold.
SalesMalformed lines are ValueError; item ids are passed to price_of unvalidated; if take itself raises midway, earlier takes are not undone.

CaughtThe enforcer's own undo was broken while its verdict passed. The measure gained 20 cases before the fix was allowed to stand.
CaughtWith all decisions in one file, an earlier installation could not be reverted once a later one followed. The judge now keeps one file per unit; three measures changed before the builds did.
CaughtMeasure writers and auditors reported gaps in the documents; eight became rules, three of them with new cases.
Selection matteredIn two of five units the alternative, not the first build, was the one that stood.
Not coveredOne session gave every unit its declarations and built the judge and the enforcer. The other agents were separate runs of the same model.
Not coveredA change to the judge is installed by the candidate judge itself; only the enforcer's run is independent of it.
Not coveredNothing forces a call to the enforcer, and nothing verifies who made a change.
Not coveredThe five installations made before the judge changed cannot be reverted alone.
